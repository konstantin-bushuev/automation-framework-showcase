# Конфигурация окружений

## Общая информация

Управление конфигурацией тестовых окружений осуществляется с помощью .properties-файлов, расположенных в общей папке config.

Папка не является отдельным Gradle-модулем. Конфигурационные файлы подключаются в качестве источника тестовых ресурсов к модулям, содержащим тесты.

Такой подход позволяет централизованно управлять настройками и использовать общую конфигурацию в разных тестовых модулях.

## Структура конфигурации

| Файл | Назначение |
|---|---|
| application.properties  | Общие настройки приложения и тестового окружения |
| timeouts.properties  | Настройки таймаутов |
| local.properties  | Локальные настройки и конфиденциальные данные |

### application.properties

Содержит общие параметры, необходимые для работы тестов:

- адреса API и Web-приложения
- настройки браузера
- параметры Android-окружения
- настройки запуска Android-тестов

Пример содержимого:

```properties
api.base.url=

web.base.url=
browser.name=

# android.deviceType=emulator
android.deviceType=real

android.emulator.device=
android.emulator.platformVersion=
android.server=
android.package=
android.activity=
android.automationName=
```

### timeouts.properties

Содержит значения таймаутов, используемых при выполнении тестов.

Пример содержимого:

```properties
timeout.api.response=
timeout.mailslurp.email=

timeout.web.default=
timeout.web.pageLoad=
timeout.web.elementWaiting=

timeout.android.default=
timeout.android.appStart=
timeout.android.elementWaiting=
```

### local.properties

Предназначен для хранения локальных настроек и конфиденциальных данных, которые не должны попадать в репозиторий:

- учетные данные тестовых пользователей
- API-ключи и другие секреты
- локальные пути к исполняемым файлам
- параметры физических устройств Android

Пример содержимого:

```properties
users.user.username=
users.user.email=
users.user.password=

admin.login=

mailslurp.api.key=

yandex.binary=

android.real.device=
android.real.platformVersion=
android.real.udid=
```

Файл local.properties исключен из системы контроля версий. Для локального запуска тестов разработчик должен самостоятельно создать и заполнить его.
В качестве образца для создания local.properties в репозитории поддерживается в актуальном состоянии файл local.properties.example.

## Порядок загрузки конфигурации

Конфигурационные файлы загружаются последовательно. Сначала считываются общие конфигурационные файлы (application.properties, timeouts.properties и другие), после чего загружается local.properties.

local.properties всегда загружается последним и имеет наивысший приоритет. При совпадении ключей его значения переопределяют значения из любых ранее загруженных конфигурационных файлов.

Такой подход позволяет локально переопределять любые параметры конфигурации без изменения общих настроек проекта.

## Организация параметров

При добавлении новых настроек следует придерживаться следующего разделения:

- application.properties — общие параметры приложения и тестового окружения, не содержащие секретов
- timeouts.properties — параметры, определяющие временные ограничения при выполнении операций
- local.properties — индивидуальные настройки разработчика, учетные данные и конфиденциальная информация
- local.properties.example — дублирует содержание local.properties, но только ключи без реальных значений

Названия параметров должны отражать их назначение и придерживаться единого стиля именования.

## Подготовка конфигурации

После получения проекта необходимо:

1. Проверить наличие конфигурационных файлов в директории config
2. Создать local.properties на основе актуального шаблона 
3. Заполнить необходимые учетные данные, API-ключи и параметры используемых устройств
4. Проверить корректность URL и остальных параметров в application.properties
5. При необходимости настроить таймауты в timeouts.properties

Перед отправкой изменений в репозиторий необходимо убедиться, что local.properties и содержащиеся в нем конфиденциальные данные не попали в коммит.
