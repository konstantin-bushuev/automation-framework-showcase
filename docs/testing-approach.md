# Подход к тестированию

## 1. Область тестирования

Тестирование направлено на проверку основных пользовательских сценариев и корректности работы приложения.

Основные направления тестирования:
- Авторизация и регистрация пользователей
- Управление профилем пользователя
- Работа с основными функциональными возможностями приложения
- Проверка взаимодействия клиента с серверной частью
- Проверка пользовательского интерфейса

Тестирование охватывает:
- API — проверка бизнес-логики и взаимодействия с сервером
- Web — проверка пользовательских сценариев в браузере
- Android — проверка пользовательских сценариев в мобильном приложении

В рамках проекта не рассматриваются:
- Нагрузочное и стресс-тестирование
- Тестирование безопасности на уровне тестирования на проникновение
- Проверка совместимости со всеми возможными устройствами и браузерами

## 2. Тест-дизвйн

Тестовые сценарии формируются на основе анализа требований, 
пользовательских историй и существующей функциональности приложения.

При разработке проверок учитываются:
- Основной пользовательский сценарий (Happy Path)
- Альтернативные сценарии использования
- Негативные сценарии и некорректные входные данные
- Граничные значения
- Взаимодействие между функциональными модулями

Используемые техники тест-дизайна:
- Классы эквивалентности
- Анализ граничных значений
- Таблицы принятия решений

Приоритизация сценариев выполняется с учётом:
- Критичности функциональности
- Частоты использования
- Влияния возможной ошибки на пользователя
- Вероятности возникновения дефектов

## 3. Ручное тестирование
Ручное тестирование применяется для проверок, которые требуют
визуальной оценки, исследовательского подхода или частого изменения
тестовых условий.

Основные направления:
- Проверка визуального соответствия интерфейса макетам
- Проверка удобства использования (Usability)
- Исследовательское тестирование (Exploratory Testing)
- Проверка новых или нестабильных функциональных возможностей
- Проверка поведения приложения в нестандартных ситуациях

Примеры сценариев:
- Оценка корректности отображения элементов интерфейса
- Проверка адаптивности Web-интерфейса
- Оценка удобства навигации
- Исследование поведения приложения при прерывании сетевого соединения
- Проверка взаимодействия с системными элементами Android

## 4. Автоматизация тестирования
Автоматизация направлена на проверку функциональности,
которая требует регулярного повторного выполнения и имеет
стабильные ожидаемые результаты.

Критерии выбора сценариев:
- Высокая критичность функциональности
- Частое выполнение проверок
- Стабильность функциональности
- Возможность однозначной проверки результата
- Целесообразность автоматизации с точки зрения затрат на поддержку

Приоритет автоматизации:
1. Критические пользовательские сценарии
2. Основная бизнес-логика
3. Часто используемые функциональные возможности
4. Негативные сценарии и проверки граничных значений

Реализованы следующие уровни автоматизации:
- API — проверка бизнес-логики, обработки запросов и ответов сервера
- Web — проверка пользовательских сценариев и взаимодействия с интерфейсом
- Android — проверка пользовательских сценариев в мобильном приложении

## 5. Ручное и автоматизированное тестирование
Выбор способа тестирования зависит от характера функциональности,
стабильности сценария и возможности автоматизированной проверки.

Распределение проверок также зависит от платформы.

API:
Автоматизация применяется практически для всех функциональных
проверок.

Исключения составляют сценарии, для которых отсутствуют необходимые
средства управления тестовыми условиями или требуется исследовательский
подход.

Например, в текущей реализации отсутствует возможность произвольно
задавать срок действия токена. Поэтому проверка доступа с просроченным
токеном выполняется вручную.

Web:
Автоматизация используется для проверки основных пользовательских
сценариев и функциональности интерфейса.

Вручную выполняются проверки визуального соответствия макетам,
адаптивности и удобства использования.

Android:
Автоматизация используется для проверки основных пользовательских
сценариев и функциональности приложения.

Вручную выполняются проверки взаимодействия с системными компонентами,
визуальных особенностей и удобства использования.

| Авторизация с некорректными данными|Авто    |Авто|Авто|
| Проверка отображения формы|-|Ручное|Ручное|
| Проверка валидации полей|Авто|Авто|Авто|
| Оценка удобства интерфейса|-|Ручное|Ручное|
| Проверка обработки ошибки сервером |Авто |- |- |
| Проверка отображения ошибки пользователю|-|Авто |Авто |
