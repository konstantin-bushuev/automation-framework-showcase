# Комплексное тестирование мультиплатформенного приложения

## Общее описание проекта

Проект представляет собой систему автоматизированного тестирования мультиплатформенного приложения для изучения английского языка с помощью игр и интерактивных упражнений.

Функциональность приложения включает:
- регистрацию и авторизацию пользователей;
- управление профилем пользователя;
- набор обучающих игр и интерактивных упражнений;
- общую систему подсчёта и отслеживания прогресса;
- административный сервис для управления заданиями.

Приложение поддерживает следующие платформы: Web, Android, iOS и общее API.

**Цели проекта:**
- Построить с нуля систему тестирования, включающую ручное тестирование и автоматизацию.
- Разработать масштабируемый тестовый фреймворк для автоматизации проверок различных платформ.

**Область автоматизированного тестирования:**
- API;
- Web UI;
- Android UI.

Для iOS на текущем этапе планируется ручное тестирование.

## Основные возможности

- API testing;
- Web UI testing;
- Android UI testing;
- поддержка нескольких окружений;
- конфигурируемые параметры запуска;
- централизованное логирование;
- генерация тестовых данных;
- переиспользование общих компонентов и базовых классов.

## Технологический стек

| Технология | Назначение |
|---|---|
| Java 21 | Основной язык фреймворка |
| Gradle | Сборка и управление зависимостями |
| JUnit 5 | Тестовый фреймворк |
| REST Assured | API-тестирование |
| Jackson | Сериализация и десериализация JSON |
| Selenium | Web UI-автоматизация |
| Appium | Android UI-автоматизация |
| DataFaker | Генерация тестовых данных |
| MailSlurp | Работа с тестовыми email-адресами |
| PostgreSQL JDBC | Доступ к БД|

## Архитектура

Проект построен на основе мультимодульной архитектуры Gradle с разделением ответственности между общими компонентами и платформенными модулями.

Основные архитектурные принципы:
- разделение тестов по платформам;
- многоуровневая организация API-тестов;
- использование Page Object / Screen Object Model для UI-тестирования;
- общие базовые классы для API- и UI-компонентов;
- централизованное управление конфигурацией;
- использование фабрик для генерации тестовых данных;
- взаимодействие с БД для диагностики и управления тестовыми данными;
- интеграция с внешними сервисами для подготовки тестовых данных.

Подробнее: [Architecture](docs/architecture.md)

## Настройки конфигурации и запуск тестов

### Конфигурация

Настройки проекта и параметры тестовых окружений задаются через файлы *.properties.

Подробнее о настройках окружения: [Configuration](docs/configuration.md)

### Запуск тестов

Для запуска тестов используются команды Gradle Wrapper. Например:

- Все тесты API:           ./gradlew :api:test
- Все тесты Web:	           ./gradlew :web:test
- Все тесты Android:	       ./gradlew :android:test
- Все тесты проекта:	       ./gradlew test
